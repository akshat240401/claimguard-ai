# Stage 1 Checklist

## Stage Goal

Create the repository foundation and lock the project scope before research or implementation begins.

## Submission Status

- Submit to Cotiviti during Stage 1: **No**
- Commit Stage 1 files to Git: **Yes**
- Push to GitHub during Stage 1: **Recommended**
- Make repository public during Stage 1: **Not required**
- Send the final submission email during Stage 1: **No**

## Required Stage 1 Files

- [ ] README.md
- [ ] PROJECT_SPEC.md
- [ ] STAGE_1_CHECKLIST.md
- [ ] .gitignore
- [ ] requirements.txt
- [ ] app.py
- [ ] data/.gitkeep
- [ ] src/__init__.py
- [ ] tests/.gitkeep
- [ ] report/.gitkeep
- [ ] presentation/.gitkeep
- [ ] screenshots/.gitkeep
- [ ] video/.gitkeep

## Scope Confirmation

- [ ] Topic 2 is selected.
- [ ] Research covers Treatment, Payment, and Operations.
- [ ] Payment is the only POC implementation focus.
- [ ] The POC supports human review.
- [ ] The POC does not determine fraud.
- [ ] The POC does not approve or deny claims.
- [ ] The project uses synthetic data.
- [ ] Treatment and Operations modules are out of scope for the prototype.

## Repository Checks

- [ ] Git repository initialized.
- [ ] Main branch is named `main`.
- [ ] No secrets or API keys are committed.
- [ ] Empty required folders are preserved with `.gitkeep`.
- [ ] Stage 1 files are staged.
- [ ] Stage 1 commit is created.
- [ ] Git status is clean after the commit.

## Recommended Commit Message

```text
Initialize ClaimGuard project scope and repository structure
```

## Stage 1 Completion Condition

Stage 1 is complete when the project structure exists, the specification is locked, the initial files are committed, and no implementation work has started outside the agreed scope.
